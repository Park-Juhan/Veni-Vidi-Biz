# 데이터셋 조사 결과

조사일: 2026-11-16 (한국 시간). 기준 문서: [decision-model-survey.md](decision-model-survey.md) 3장의 출처 후보.
방법: 공식 포털(공공데이터포털, 서울 열린데이터광장, KOSIS, R-ONE) 페이지와 검색 결과 확인.

> **확인 수준 표기**
> ✅ 공식 페이지로 제공 형태 확인 · 🔶 존재는 확인, 세부 명세(요청 변수·응답 필드·트래픽 한도)는 활용신청 후 명세서로 확인 필요 · ❔ 미확인
> 이번 조사에서는 API를 실제로 호출하지 않았다. 인증키 발급과 시험 호출은 DB 설계 전 마지막 확인 단계로 남긴다.

## 1. 핵심 결론

1. **상권 지표(추정매출·유동인구)는 서울만 API로 받을 수 있다.** 서울 열린데이터광장의 상권분석서비스 데이터는 분기별 추정매출·길단위인구·점포·상권변화지표를 상권 단위로 제공한다. 전국 단위 추정매출·유동인구는 소상공인365 웹 화면으로만 확인되고, API는 찾지 못했다.
2. **전국 단위로 받을 수 있는 입지 데이터는 "점포 위치·업종"과 "인허가·폐업 이력"이다.** 경쟁 점포 밀도와 업종별 생존·폐업 위험 계산에는 충분하다.
3. **임대료·업종 비용 구조는 지역·업종 평균 통계뿐이다.** 개별 매물 임대료는 공개 데이터로 얻을 수 없다. 사용자 입력값을 평균과 비교하는 용도로 쓴다.
4. **재료 시세는 농축수산물만 있다.** 원두·우유·포장재 같은 가공품과 소모품은 사용자 입력이 필요하다.
5. **메뉴 판매량·캠페인 성과는 공개 데이터가 없다.** 메뉴 엔지니어링과 마케팅 성과 비교는 사용자 기록을 DB에 쌓아야만 동작한다.

## 2. 데이터셋별 조사 결과

### 2.1 입지·상권 (property)

|---|---|---|---|---|---|---|---|
| 서울시 상권분석서비스: 추정매출 | 서울 열린데이터광장 / 공공데이터포털 | 서울, 상권·행정동·자치구 × 업종, 성별·연령·주중/주말 매출과 건수 | Open API (1회 1,000건), 파일 | 분기 (약 2개월 뒤 공개) | 공공데이터포털 메타데이터상 제한 없음 | ✅ | 후보 상권의 업종 매출 수준 → 자가평가 "고객층 적합도" 대체 |

## 4. DB 설계 반영 사항

- **외부 데이터 테이블은 원본 그대로가 아니라 필요한 집계만 저장한다.** 상가(상권)정보는 전국 업소 단위라 규모가 크다. "지역 × 업종별 점포 수"처럼 모델이 쓰는 단위로 집계해 저장하거나, 반경 조회는 API를 그때그때 호출한다.
- **모든 외부 데이터 행에 메타데이터를 저장한다.** 출처 기관, 데이터셋 이름, 기준 시점(분기·연도), 수집일, 이용 조건. 화면 결과에 출처와 기준 시점을 표시한다.
- **업종 코드 매핑 테이블이 필요하다.** 서울 상권분석 업종 코드, 상가정보 표준산업분류 기반 247개 업종, 인허가 업종, 실태조사 업종 분류가 서로 다르다. 앱의 업종 선택값과 각 출처 코드를 연결한다.
- **지역 코드 매핑이 필요하다.** 행정동 코드, 서울 상권 코드, 시도·시군구 코드를 연결한다.
- **API 키는 코드나 DB에 넣지 않고 환경변수(`.env`, Git 제외 대상)로 관리한다.**
