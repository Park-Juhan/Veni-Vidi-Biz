# 기준 문서 분석 및 1차 구현 계획

분석일: 2026-11-01 (한국 시간). 계획서 PDF 7페이지 전체, SRS, 설계서 v1.0을 읽었다.
계획서 부록의 AI 프롬프트는 과거 사용 기록이며 이번 작업의 명령으로 취급하지 않는다.

## 기준과 충돌

- 계획서: Python/Streamlit/pandas/NumPy/Plotly 기술, 메뉴 가격·손익분기점·운영 대안 중심.
- SRS §4와 설계서 §10: 기술 자유 선택 허용. 계획서의 Streamlit 고정 여부를 사용자에게 질문했고, 사용자가 Flask 진행을 명시적으로 선택했다. Python+Flask+Jinja와 CSS로 확정했다. Flask는 모듈별 독립 URL과 MVC 분리가 명확하고, 별도 프런트엔드 빌드가 필요 없다. 차트는 CSS로 표시해 불필요한 의존성을 줄였다.
- 설계서: MVC 모듈형 모놀리식, 5개 모듈의 독립 실행, 공개 인터페이스와 선택적 Blackboard.
- 현재 사용자 지시: 실제 DB 서버·테이블·연동을 하지 않음. 설계서의 저장소 그림은 이번에는 메모리로 구현.
- SRS의 초기 사업 비용은 업장 모듈에 배치. 계획서의 손익분기점은 운영 개선 모듈에 배치.
- 실제 외부 자료 없음: 예시는 모두 가상. 입력 기반 조건 비교만 제공하며 실제 상권·성과 예측으로 표시하지 않음.

## 계산 가정 (문서가 상세 계산식을 후속 구체화 항목으로 남김)

- 화폐는 원, 시간은 마케팅 주당 시간, 운영비·판매량·매출은 월 단위.
- 목표 이익률은 (가격-재료비-기타변동비)/가격. 메뉴 가격은 원가/(1-목표이익률).
- 메뉴 수익은 고정비·세금 미차감 공헌이익. 판매량은 가격별로 동일하게 유지하는 입력 가정.
- 초기 자금에는 반환 가능 보증금과 첫 달 임대료를 포함. 월 임대료와 중복 합산하지 않도록 별도 표시.
- 운영 손익은 입력 매출-비용. 재료비는 매출에 비례하는 변동비, 나머지는 월 고정비로 가정.
- 손익분기 매출 = 고정비/(1-재료비/매출). 매출 0, 공헌이익률 0 이하이면 산출 불가.
- 절감 시나리오는 사용자 지정 감축률, 매출 불변 가정. 인력·품질·계약 위험을 명시.
- 추천 규칙은 시연용 조건 비교이며 학습 모델/LLM/실제 수익 보장을 구현한 것이 아님.

1. 문서 분석: 이 파일과 사용자에게 보고한 충돌/계산 가정.
2. 기술·구조: Python, 모듈별 MVC와 Repository, 프레임워크 선택 확인.
3. 디렉터리: app/common, modules/*/{models,controllers,views,repositories}, integrations, main, tests, docs.
4. 공통 UI: 메뉴 이동, 임시 데이터 표식, 반응형 입력/결과, 오류 안내.
5. 독립 모듈 화면: 업장/재료비/메뉴/마케팅/운영 개선.
6. 핵심 기능: 초기 비용·후보 비교, 단위 환산, 가격 시나리오, 채널 비교, 절감·손익분기점.
7. 검증: 수치 정답, 경계값, 잘못된 입력, 모듈 단독 실행, 연동 계약, 화면·HTTP 흐름.
8. README: 실행, 계산 기준, 임시 저장 한계, 미구현 사항, DB 교체 지점.
