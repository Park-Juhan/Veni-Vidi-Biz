# 의사결정 모델 조사 및 필요 데이터 정리

작성일: 2026-11-16 (한국 시간). 대상: 1차 구현의 5개 모듈 (`app/modules/*/models`).
목적: 모듈별로 "무엇을 판단하는가 → 어떤 모델을 쓸 수 있는가 → 그 모델에 어떤 데이터가 필요한가"를 정리해
다음 단계(데이터셋 조사 → DB 설계 → UI 수정)의 기준으로 삼는다.

> 데이터 출처는 후보 목록이다. API 제공 여부·라이선스·갱신 주기·지역 범위는 다음 단계(데이터셋 조사)에서 확인해야 한다.

## 1. 현재 상태 요약

| 모듈 | 판단 질문 | 현재 방식 (코드 기준) | 한계 |
|---|---|---|---|
| 부동산·업장 `property` | 후보 2곳 중 어디가 나은가, 초기 자금이 충분한가 | 고정 가중합 점수: 고객층 6×, 동선 4×, 시설 2× (각 1~5 자가평가) + 예산 이내 25점 + 면적 충족 15점 | 가중치 고정, 입지 지표가 전부 주관 평가, 후보 2곳 고정, 매출 추정 없음 |
| 재료비 `material_cost` | 재료 1회 사용 원가는 얼마인가 | 단가 × 수량 → 기준 단위 원가 × 사용량 (단위 환산) | 단일 재료, 폐기율·수율 없음, 가격 변동 반영 없음 |
| 메뉴 가격 `menu_pricing` | 메뉴를 얼마에 팔아야 하나 | 원가 가산: 변동원가 ÷ (1 − 목표 공헌이익률), 100원 올림, 3개 가격 비교 | 판매량을 가격과 무관하게 고정, 경쟁 가격·수요 반응 없음, 메뉴 1개씩만 |
| 마케팅 `marketing` | 어떤 홍보 방법을 쓸까 | 가상 채널 3개 규칙 점수 (고객층 +2, 목적 +2, 1인 저시간 +1), 예산·시간 필터 | 채널·비용이 가상 값, 효과(유입·매출) 추정 없음, 예산 배분 없음 |
| 운영 개선 `cost_optimization` | 어디서 비용을 줄이고 손익분기는 얼마인가 | CVP: 손익분기 매출 = 고정비 ÷ (1 − 재료비/매출), 사용자 입력 감축률 시나리오 | 비교 기준(업종 평균) 없음, 감축률이 임의값, 불확실성 반영 없음 |

## 2. 모듈별 후보 모델

### 2.1 부동산·업장 — 다기준 의사결정(MCDA) + 상권 지표

| 후보 모델 | 내용 | 장점 | 필요 데이터 | 난이도 |
|---|---|---|---|---|
| **가중치 사용자 설정 + TOPSIS** (권장 1단계) | 기준별 가중치를 사용자가 정하고, 이상해와의 거리로 후보 순위 산출. 후보 N곳 지원 | 현재 가중합 구조를 거의 그대로 확장, 설명 가능 | 후보별 기준값 (임대료, 면적, 아래 상권 지표) | 낮음 |
| AHP (쌍대비교 가중치) | 기준 간 중요도를 쌍대 비교해 가중치 도출, 일관성 비율 검사 | 가중치 근거를 명확히 남김 | 사용자 쌍대 비교 입력 | 낮음~중간 |
| 상권 지표 기반 점수 (자가평가 대체) | 1~5 자가평가를 유동인구·동종 점포 수·추정 매출·개폐업률 등 실측 지표로 교체 | 객관성 확보, 설명 시 근거 제시 | 상권 단위 유동인구·점포·매출·개폐업 데이터 | 중간 (데이터 의존) |
| Huff 모델 (상권 흡인력) | 거리와 매장 매력도로 후보 위치의 고객 흡수 확률 추정 → 예상 매출 | 입지별 매출 추정 가능 | 좌표, 경쟁 점포 위치·규모, 인구 분포 | 높음 |
| 생존 분석 (지역·업종별 폐업률) | 같은 업종·지역 점포의 생존 기간 분포로 위험도 제시 | 위험 지표로 유용 | 인허가·폐업 이력 | 중간 |

### 2.2 재료비 — 계산 정밀화 + 가격 추세

| 후보 모델 | 내용 | 필요 데이터 | 난이도 |
|---|---|---|---|
| **레시피(BOM) 합산** (권장) | 메뉴 = 재료 N개 × 사용량, 메뉴 원가 자동 합산 | 재료 목록, 레시피 구성 (사용자 입력) | 낮음 |
| **수율·폐기율 보정** (권장) | 실사용 원가 = 원가 ÷ 수율, 손질·폐기 손실 반영 | 재료별 수율 기본값 (사용자 입력 또는 참고값) | 낮음 |
| 가격 추세·변동성 경고 | 품목 시세의 이동평균·변동폭으로 원가 상승 위험 표시 | 품목별 가격 시계열 | 중간 |
| 원가 예측 (단순 시계열) | 시세 시계열로 다음 달 원가 범위 예측 | 장기 가격 시계열 | 중간~높음 |

### 2.3 메뉴 가격 — 원가 가산 → 수요 반영

| 후보 모델 | 내용 | 필요 데이터 | 난이도 |
|---|---|---|---|
| **경쟁 가격 벤치마크** (권장 1단계) | 원가 기준 가격을 주변·업종 평균 가격대와 함께 표시 | 업종·지역 메뉴 가격 (수집 또는 사용자 입력) | 낮음 |
| **메뉴 엔지니어링 (인기도 × 공헌이익 매트릭스)** (권장) | 메뉴를 Star / Plowhorse / Puzzle / Dog 4분면으로 분류해 가격 조정·메뉴 정리 판단 | 메뉴별 판매량·원가 (매장 판매 기록) | 낮음 (데이터는 DB 필요) |
| 가격 탄력성 기반 이익 최대화 | 수요곡선(선형 또는 상수 탄력성)을 가정해 이익 최대 가격 탐색, 탄력성은 사용자 가정 또는 판매 기록으로 추정 | 가격 변경 전후 판매량 (추정 시) | 중간 |
| 손익분기 판매량 연동 | 운영 고정비를 받아 메뉴 가격별 손익분기 판매량 표시 | 운영 개선 모듈의 고정비 (모듈 연동) | 낮음 |

### 2.4 마케팅 — 규칙 점수 → 예산 배분 + 효과 측정

| 후보 모델 | 내용 | 필요 데이터 | 난이도 |
|---|---|---|---|
| **채널 카탈로그 + 제약 최적화** (권장 1단계) | 예산·시간 제약 안에서 기대 효과 합이 최대가 되는 채널 조합 선택 (0-1 배낭 문제) | 채널별 비용·시간·기대 효과 범위 (참고값 + 사용자 수정) | 낮음~중간 |
| **캠페인 기록 기반 성과 비교** (권장) | 실행한 홍보의 비용 대비 신규 고객·매출 변화 (CAC, ROI)를 전후 비교로 기록 | 캠페인 기록, 기간별 매출·방문 (매장 데이터) | 낮음 (데이터는 DB 필요) |
| 다중 슬롯머신(밴딧) 예산 재배분 | 성과 기록이 쌓이면 효과 좋은 채널에 예산을 점진적으로 이동 | 반복된 캠페인 성과 기록 | 높음 |

광고 성과에 대한 공개 데이터는 부족할 가능성이 크다. 사용자 매장의 실행 기록을 쌓는 구조(DB)가 우선이다.

### 2.5 운영 개선 — CVP 유지 + 기준값·불확실성

| 후보 모델 | 내용 | 필요 데이터 | 난이도 |
|---|---|---|---|
| **업종 평균 비용 구조 벤치마크** (권장) | 항목별 비중을 업종 평균과 비교해 "평균보다 높은 항목"을 절감 후보로 제시 (임의 감축률 대체) | 업종·규모별 매출·비용 구조 통계 | 낮음 (데이터 의존) |
| **민감도 분석** (권장) | 매출·재료비율·임대료가 ±10~30% 변할 때 손익·손익분기 변화 표시 | 현재 입력값으로 충분 | 낮음 |
| 몬테카를로 시뮬레이션 | 매출·비용을 범위로 입력받아 적자 확률 추정 | 입력 범위 (최소·최대) | 중간 |
| 매출 예측 (시계열) | 월별 매출 기록으로 계절성·추세 예측 후 손익 전망 | 매장 월별 매출 기록 (12개월 이상 권장) | 중간~높음 |

## 4. DB 설계에 주는 영향

조사 결과 데이터는 세 종류로 나뉜다. DB는 이 세 종류를 모두 담아야 한다.

1. **사용자 입력·계산 결과**: 현재 메모리 Repository가 담는 것. 작업 공간, 모듈별 입력·결과 이력.
2. **사용자 운영 기록 (신규)**: 재료·레시피, 메뉴, 판매 기록, 월별 매출·비용, 캠페인 기록, 입지 후보 N곳.
   메뉴 엔지니어링, 캠페인 성과 비교, 매출 예측처럼 권장 모델 상당수가 이 기록을 필요로 한다.
3. **외부 참고 데이터 (신규)**: 상권 지표, 시세, 업종 평균. 출처·기준일·라이선스·수집일을 함께 저장해 화면에 출처를 표시한다.

## 5. 권장 진행 순서

| 순서 | 작업 | 이유 |
|---|---|---|
| 1 | 데이터셋 조사: 3장 목록의 API 여부·라이선스·지역 범위·갱신 주기 확인 | 상권 지표·업종 평균이 실제로 확보되는지에 따라 property·cost_optimization 모델이 결정됨 |
| 2 | DB 설계·생성: 4장의 세 종류 데이터 스키마 | 레시피·판매·캠페인 기록이 있어야 권장 모델 다수가 동작 |
| 3 | 데이터 없이 바로 가능한 모델 구현 | 레시피 합산·수율, 민감도 분석, 가중치 설정 + TOPSIS, 손익분기 판매량 연동 |
| 4 | 데이터 의존 모델 구현 | 상권 지표 점수, 업종 평균 벤치마크, 메뉴 엔지니어링, 캠페인 성과 비교 |
| 5 | UI 수정 | 가중치 입력, 후보 N곳, 레시피 편집, 기록 입력 화면, 출처 표시 |
